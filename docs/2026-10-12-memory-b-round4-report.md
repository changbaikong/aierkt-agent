## 7 项缺口的修法

| 编号 | 原缺口 | 现在的做法 |
|---|---|---|
| B3-R1 | 同一回合里任意一句「同意」都能给别的建议盖章 | 采纳表达必须与**这条内容说的事**对上，且要求至少两处共同实义片段；跨句指代确认（「那就按这个来吧」）仍认 |
| B3-R2 | 只要包里有任意工具回执就放行 | 回执必须**说到要改的这件事**，且不能是失败结果；「查询成功」但与该事项无关的不算 |
| B3-R3 | 有一个变化值命中就整条放行 | 逐项核对；用户说未定的字段不许填值 |
| B3-R4 | 等值数字（三千 / 3000）被当成不同值而拒绝 | 按值比对，认数词与阿拉伯数字、含单位 |
| B3-R5 | 新增候选借替代字段绕过保护归档旧记录 | 所有会改旧记忆的入口共用同一套来源、事项、状态规则；候选入库与替代生效分开判 |
| B3-R6 | 通知回调抛异常仍回执「同步已发出」 | 如实记失败；留下可恢复的待同步标记供下轮对账 |
| B3-R7 | 短期语义丢失、无到期时间 | 提炼侧声明的时间尺度真传下来并落库，接入现有到期政策 |

## 本轮新发现的程序问题（合成反例没覆盖）

1. **明确决定被降级**：用户说「这个项目暂时先不部署」「项目日志一律先落盘再回传」，模型 3/3 正确识别为已决定，程序却降成待建议。根因是判决定的词表**写好了但从未被调用**（死代码）——第三轮声称修好的「直接表达决定」实际没生效。
2. **换词被当成「新值没依据」**：用户「改用方案B，不再用方案A；还没有实施」，模型把「用」写成「使用」、「选择」写成「决定」，程序三次把整条正当替代拒掉。现在只有「替代」动作按带值的片段逐项取证，「纠正」仍严格逐项核对。
3. **修 R5 时打破了本轮之前已通过的测试**：`packet` 为空被当成硬拒绝，而程序内直连调用本来就不带处理包。现已区分「调用方语境」与「模型产出候选」。
4. **条件句漏判**：提问、「先不要决定」、「如果不累的话就一律先落盘」这类**设想**都被记成已决定。条件的作用域按整句判（逗号不算断句），否则后半句会漏过去。
5. **一个普通词就能当桥**：用户说「排期方案暂不调整」，模型输出「部署方案立即执行」也被记成已决定 —— 两件事只共用「方案」。现要求至少两处共同实义片段。
6. **误伤**：「就照我刚才说的话一律先落盘」被「的话」误判成条件句。现只有「的话」后面紧跟「就／便／才／再」才算条件。

独立验收在过程中另证伪出 6 条真实缺陷并确认修复，包括两处硬缺陷：维护判定里变量未赋值导致崩溃、证据字符串被按单字拆开导致所有普通纠正被误拒。

## 未验证范围与遗留项

- 独立验收的反例全部是**手工构造的合成对抗输出**，只证明程序会/不会接受哪些输出，**不代表真实模型产生这类错误的频率**；其脚本的 `live_model_calls=0`。
- f 组用的是真实用户措辞，但模型条目是手搭的，不是真实模型输出。
- 条件句修复前的旧字节已被覆盖，**无法独立复现**当时的漏判，只能确认修复后已拦住。
- **两条遗留误拒**（保守方向，均已保留在证据里）：用户原话「改用方案B，不再用方案A，预算八千」时，替换内容里的「八千」被判为没依据（与「只认讲目标事项的句子」这一取舍有关）；「一律」会被切成数值片段「一」而要求依据，拒绝理由误导。
- 真实模型批次只覆盖提炼模型的保存、更新、状态与跨会话召回；检索向量用确定性替身，**没有验证真实向量模型排序质量、完整网页回答链、生产云服务与长跑**。
- 「一年后维护」是模拟时钟推进，不是真实长跑成绩。
- 每类样例仅 3 次，样本量小，不能据此推断总体错误率；36/36 只说明本批样例全部符合要求。
- 规则初筛通过不等于语义终审；原始输出已全部留存，建议保留端到端人工复核。
