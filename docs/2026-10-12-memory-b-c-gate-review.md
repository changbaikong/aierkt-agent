# B 收尾独立验收与 C 进入门槛

日期：2026-10-12。对象：当前本机工作区的 B 收尾版本，以及 C 统一上下文编排计划。
本轮只验收并更新证据、探针与文档；没有维修产品逻辑、调整正式配置、触碰生产记忆或部署。

## 判定

2026-10-13 最新更新：按用户后续要求改为模型承担主要语义判断，判断、理由和引用供后续代理看见并纠正。全量测试日志记录2899项和119个子检查通过，六份隔离脚本及双端HTTP通过；真实复验仍有30秒超时、阶段期限错误、明确认同漏存及旧决定继续召回。计划54批在8批落盘后有界停止，完整真实验收未完成；**B 未完成，C 真实记忆整链仍不放行**。详见 [最新修复暂停与独立结果](2026-10-13-memory-model-led-final-review.md)。此前 [修复暂停记录](2026-10-13-memory-b-repair-paused.md) 和 [独立复审](2026-10-13-memory-b-repair-code-review.md) 为历史快照，不直接代表后续修复版本。下方保留2026-10-12原始验收内容，不将旧成绩当作修后成绩。

**B 仍不通过完整验收。C 可以开始隔离框架、离线编排和测试，不能以 B 已完成为前提启用真实记忆整链。**

C 原计划已经允许这两种进度分开报告。本轮发现的是记忆内容、有效状态及期限错误；统一挑选背景无法恢复没有保存的新决定，也无法把被误存的假事实变真。因此不能通过 C 的排序、压缩或提示词替 B 掩盖问题。

旧修复有真实进展：原反例和新增收尾检查均通过，正常阶段约束也不再一天后失效。但“替代旧记录”路径的保护不等于所有写入入口都受保护，“生成了核对回执”也不等于不通过时停止入库。

## 五个独立反例

以下使用合成的提炼输出，经过真实解析与保存入口，存储和向量均隔离。它们证明程序边界，不代表真实模型产生错误的频率。

| 情形 | 用户原话与候选 | 实际结果 | 判定 |
| --- | --- | --- | --- |
| 新建假预算 | 原话“项目预算为3000元”；候选写9000元 | 9000 成为长期有效事实，核对回执还显示通过 | 阻断 B：新建入口没有逐值依据保护 |
| 新建假评审 | 原话改用 B、尚未实施、没有评审结论；候选附“安全评审已通过” | 核对回执不通过，假评审仍作为有效决定保存 | 阻断 B：回执没有成为写入门槛 |
| 不同事项串期限 | 日志长期原则；另一个临时提醒保留三天 | 日志原则被套三天期限，模拟四天后过期 | 阻断 B：期限没有绑定到具体事项 |
| 普通分析请求误长期化 | 原话“云端部署的建议你再分析一下”；短期候选“要求继续分析” | 被认作项目阶段约束，无到期时间 | 阻断 B：阶段判断依赖候选措辞 |
| 明确短句认同的回执假拒 | 唯一历史提议“以后回答先说结论可以吗”；用户“嗯，就这样” | 偏好已保存，但回执说“以后”没有依据 | 核对口径不一致；直接拦所有不通过回执会误伤正确保存 |

两个正常对照分别使用原值3000及不含假评审的 B 选择，均正确保存。阶段约束本身应该持续到明确替代或取消；问题在于把不相干期限和普通请求当成阶段约束。

## 新真实批次的独立核对

模型：deepseek-flash。六类为 Q3、Q7、Q10、Q14、Q16、Q17，每类重复三次。原始输出、保存状态、更新回执保留在证据中；没有把旧 v7 的54/54成绩当作本轮结果。

| 记录 | 独立观察 | 与自动成绩的关系 |
| --- | --- | --- |
| Q3-1、Q3-3 | 明确认同的偏好有效保存；“以后”范围却被回执判为无依据，历史提议实际包含这个范围 | 自动均通过，回执质量被漏掉 |
| Q7-1 | 提炼或应用检查异常，无可用原始输出 | 自动失败；原因未诊断，不推断为网络或余额问题 |
| Q7-3 | 模型声明短期的再次分析请求，被“尚未给出结论”提升为长期阶段约束 | 自动通过，期限误判被漏掉 |
| Q14-3 | 用户明确改用 B，替代写入却标为待建议 | 自动通过，选择状态被漏掉 |
| Q16 三次 | 暂不部署、继续本机验收保持已决定状态；模拟两天后仍有效 | 这是已修好部分 |
| Q17-1、Q17-3 | 替代因“动作”“决定”等措辞拒绝，隔离重放后旧立即执行仍有效并被新会话召回 | 自动失败；实际后果已补证 |
| Q17-2 | 替代应用成功，但把助手说的“先放本机”写成用户决定；排期不调整又标成待建议 | 自动通过，来源与状态被漏掉 |

Q17 三条模型候选都夹带了用户未说的“本机”，该细节来自助手回答。因此不能说两条被拒内容全部忠实，也不能把修法定成无条件放宽。正确处理应保存有依据的“不部署”，对无依据的位置细节拒绝或隔离；不能让整个新决定消失，也不能按措辞差异随意放行。

Q10 没有把助手自称“全部通过、可上生产”升为已核实完成；无对象原话的开放问题是否值得长期保留仍有噪声风险，本轮不把它强行判成明确错误。

不另造一个总的“语义通过率”：当前小批覆盖六类，自动规则漏项、未知异常与混合来源需要分别报告。

## 为什么还不能按最终收尾完成

1. 新建和替代的防线不同：新建没有旧正文时，假数值可以通过；评审检查即使发现问题，也没有阻止新建保存。
2. 核对仅输出了说明，部分入口没有执行它的结论。对短句认同，核对又没有正确继承唯一被认同的历史内容。
3. 期限取整轮原话，阶段属性取模型措辞，导致同轮不同事项的寿命互相影响。
4. 最终收尾报告自己承认没有实现“必要时语义复核”，不确定内容直接拒绝；本轮仍复现拒写后旧决定继续生效。
5. 自动验收与产品共用部分判据；Q14 未配置完整选择更新检查，Q17 对状态与来源也不完整。自动全过不能替代独立逐条核对。

这不是重新设计全部记忆类型的理由。当前优先统一写入依据、事项绑定、维护失败状态及验收口径；继续增加类型无法修复这些入口缺口。

## C 的当前允许范围

| 工作 | 当前判定 |
| --- | --- |
| 输入契约、候选整理、任务排序、空间预算、历史整理 | 可先在隔离数据下开发与验证 |
| 主回答、搜索、核查和收尾的输入一致性 | 可用固定记忆与模拟证据验证 |
| 无额外执行或记忆写入的影子对照 | 可在明确隔离、未启用真实记忆整链的前提下准备和测试 |
| 将当前 B 的真实记忆自动接入所有回答入口并宣布主链可靠 | 暂不放行 |
| 生产启用、数据变更、部署或推送 | 本轮未做；本轮验收不构成授权 |

本轮没有开始实现 C；只是明确进入门槛。C 原计划继续复用 A/B，不能顺便重写保存语义。

## B 最小剩余收尾要求

- 所有新建、纠正、替代与合并入口共用同一依据规则；假预算、假评审即使带合法来源编号也不能成为有效事实。先修核对对短认同的来源口径，再让“不通过”真正阻断有效写入。
- 核对以信息为单位，区分转述与新增事实，保留正常改写对照；必要的自动语义复核或等效可靠机制必须落地并有结果。无依据的细节不能随用户明确新决定一起生效，也不能使旧相反决定一直冒充现行状态。
- 保留时间绑定到具体事项；阶段约束核对用户原话，普通分析请求不能因模型多写“继续”“尚未”就永久化。
- 验收直接核对已选择状态、到期状态、核对回执、来源和新会话召回，不把产品同一套判据当成唯一答案。纳入本轮五个反例、正常对照及 Q17 重放。
- 修后冻结版本，重跑必要离线范围和完整真实质量批次，保留失败调用及原始证据；通过后再打开 C 的真实记忆依赖。生产装配和连续运行仍需另验。
