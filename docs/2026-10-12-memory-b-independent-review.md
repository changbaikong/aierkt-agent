## 阻塞一：换方案会夹带无依据的事实

用户原话：“部署方案改用方案B，不再用方案A；尚未实施，也没有评审结论。”

正常候选“部署方案改用方案B”成功保存，这是必要的正常对照。但以下两条手工构造的错误模型输出也都被接收，旧方案归档，新条目保存为已采纳：

- “部署方案改用方案B，安全评审已通过”。
- “部署方案改用方案B，回滚演练已经成功”。

这证明的是程序保护缺口，不声称本轮真实模型产生过这两条输出。既有第五轮 W8 用“实施窗口已获批准”也复现相同缺口。

根因：为允许“用/使用/决定”等正常改写，替代动作只对数字、编号等带值片段核对出处，非数字的新结论被整体跳过。正常转述和新事实没有分开判断。

最新修复报告未列出这条仍失败的既有反例，只报告最终脚本的 26 项必需检查和两条保守误拒；这些成绩不能替代 W8。把问题称为“已知代价”也不改变原计划“不凭模型自述证明核实/完成”的要求，本轮未取得用户放弃这一要求的指示。

建议后续修复：按内容逐项区分原选择的改写与新增评审、审批、执行结果；新增事实必须对应原话或可信工具证据。两条错误变体必须拒绝，正常“改用B、尚未实施”必须继续保存，不把所有替代一律拦住。

## 阻塞二：阶段约束被当成当天情绪处理

真实输入：“这个项目暂时先不部署，继续做本机验收。”三次模型都正确标成已采纳的决定，但都声明 short_term（短期）。程序无条件给一天有效期，记录在模拟两天后的维护中全部失效。

原 B 维修计划明确写着：“业务决策 active 直到明确被替代、失效或归档”。用户没有说“仅今天不部署”，也没有给截止日期。“暂时”说明当前阶段的安排，不能据此推导一天后允许忘记该约束。

模型对时间尺度的理解不稳，程序也未区分项目阶段约束与当天情绪。因此独立复核保留规则评分 36/36，同时把符合完整保留要求的结果记为 **33/36**，没有覆盖原始评分或删除失败样例。

建议后续修复：当天情绪可按短期清理；项目阶段约束应保留到明确替代、取消或可核实的结束条件。有用户明示的日期或时长才设置相应到期时间。继续验证“不部署”不会变成“已部署”，且无需额外要求用户确认。

## 两条仍存在的误拒

最终证伪脚本仍确认：同轮“改用方案B，不再用方案A，预算八千”可能把确有依据的“八千”拒掉；“一律”被切出中文数词“一”，可能因所谓数值缺依据拒绝正常改写。它们偏向拒绝正当更新，与上述允许错误事实写入是不同方向的问题，均保留，不合并成一条模糊的“质量问题”。

## 已改善的实际行为

正常陈述可以自动保存，不需要逐条下达保存指令；没有下一条回复不阻塞已发布回合处理；多个建议只回“嗯”保持建议，唯一明确对象的短句认同能形成偏好。预算纠正、等值数字、新旧版本关系、故障重试、短期情绪到期、失败同步回执以及隔离双端传递均在本轮对应检查中通过。

日志原则三次都保留长期语义，今天疲惫的两条记录在模拟到期维护后正确失效。模型将日志原则两次标为明确偏好、一次标为已采纳决策，未发现本批次因此丢失原则；仍应按用途验证后续更新，不能靠类别名宣称语义边界天然可靠。

## 验收工具与未覆盖范围

- 初次“按 memory 关键字选测试”额外选中了 Windows 沙箱的内存限制用例，因系统拒绝创建隔离配置失败；498 项及 59 个子检查通过、1 项系统权限失败。随后按明确的记忆测试文件复跑，483 项及 59 个子检查通过。没有把系统权限故障归为 B 缺陷，也没有声称初次命令退出码为 0。
- 一次测试收集撞上同时删除的模型探针临时目录；明确测试根目录与收集边界后复跑通过，未改产品断言。
- 初次真实批次 36 次进度均显示通过，但末尾证据写入被系统权限拒绝，未留完整原始输出，退出码为 1，不纳入正式评分。本轮另跑正式 36 次，通过返回值捕获原始输出，用文件编辑工具保存；该批次退出码为 0，用量 48,247 个 token。两次调用成本不能只报正式批次用量为总成本。
- 离线包装仅截获旧报告路径的写文件操作，防止覆盖历史并绕过证据文件权限异常；产品保存、队列、断言、拒绝理由和脚本退出规则均未修改。
- 真实提炼使用当前项目配置，检索向量使用确定性替身；未重验真实向量排序、完整网页回答链、生产云装配、生产数据一致性或真实长跑。
- 真实质量脚本的处理包默认会话范围，虽带项目绑定，也不足以证明每条新项目约束均可跨会话召回。已有预算/选择的跨会话检查通过，不推广到全部新建内容。
