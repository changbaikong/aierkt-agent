# 自主 Work 代码代理正式路线图

版本：2026-09-30 阶段 4 验收通过版
状态：阶段 0 至阶段 4 全部完成；2026-09-30 矩阵与 30 回合网页验收通过，自动回写保持关闭
定位：本文档是后续设计、施工和验收的唯一决策基线。历史讨论、临时方案和已否决选项不再具有约束力。

## 1. 目标

把现有 Work 从“执行少量预设后台任务”升级为独立代码代理。完成后的代理能够：

- 检查受允许的项目工作区。
- 查询当前用户范围内的知识库。
- 在需要时通过宿主网络代理搜索和读取资料。
- 修改任务快照中的代码和测试。
- 使用受管理的 PowerShell 7、Python 3.12 和代码搜索工具进行实验与验证。
- 读取工具、命令和测试反馈，持续修正，直到完成、需要审批或确认无法继续。
- 在满足低风险规则时安全回写；否则把差异交给用户审批。

第一版只覆盖代码工作闭环，不扩展到通用桌面自动化、发布、推送、系统设置修改或沙箱内任意联网。

## 2. 当前状态

阶段 0、阶段 1、阶段 2、阶段 3 已完成并经过全量验证；阶段 4 已于 2026-09-30 完成矩阵与 30 回合网页验收：

- Work 提交不再走确定性硬路由，运行时只能给主模型建议。
- 工具效果统一为 `read / transient / persistent`。
- 动作网关在执行前完成必填字符串和工具自定义跨字段校验。
- 低风险持久动作具有独立一致性复核和闭合覆盖测试。
- `work__submit` 的输入要求由 Work 领域维护，路由只读，不拥有执行权。
- 缺少 `system.volume.adjust.input.percent` 时拒绝执行；明确的 `percent=0` 表示静音。
- `WorkHost.submit()` 不重复做参数完整性校验，兼容参数可从 `input or context` 取得的既有接口。

阶段 1 新增无模型 Windows 沙箱：真实 AppContainer、目录权限、Job Object、受管入口白名单、暂停启动、句柄白名单、超时和取消、输出与内存限制、磁盘软上限、状态清单和清理；隔离能力不可用时失败关闭。

阶段 2 新增显式 `code.agent` 提交、独立快照与代码 worker、精简模型工具循环、原对话知识检索、受限宿主网络代理、持久审批恢复和只展示不回写的补丁工件。真实端到端验收证明命令运行于 AppContainer、沙箱无法连接宿主回环地址且原项目保持不变。

阶段 3 新增宿主可信测试配置、固定内容风险清单、跨进程项目锁、冲突与路径身份检查、可恢复逐文件事务、Windows 原子替换竞争保护、回写后隔离复验以及审批绑定。自动回写功能开关仍默认关闭。

## 3. 固定架构

### 3.1 主模型

主模型负责判断请求应当直接回答、调用具体工具、查询知识或网络、提交 Work，还是派给代码代理。路由规则可以提供建议，但不能绕过模型替用户创建持久任务。

### 3.2 WorkHost

`WorkHost` 只负责队列、Attempt、审批、取消、持久化、恢复和结果回传，不负责模型推理或沙箱内部执行策略。代码任务必须使用独立 worker 池，不能占满现有短任务队列。

### 3.3 CodeAgentLoop

代码代理新建精简的 `CodeAgentLoop`，不复用聊天 `AgentLoop`。它只保留模型消息历史、步骤和预算、工具调用反馈及审批恢复检查点，不包含聊天双轨消息、开场白、人物状态、意图闸门或聊天润色。

`CodeAgentLoop` 返回内部 `CodeAgentOutcome`，由 `CodeAgentProvider` 翻译为 `WorkResult`。

### 3.4 ActionGateway

所有文件、命令、网络和回写动作统一经过 `ActionGateway`。网关负责参数、权限、作用域、风险、审批暂停和恢复。拒绝某个动作不等于取消代码任务；拒绝结果必须返回模型，使其可以选择替代方案。

### 3.5 Windows 沙箱

代码和命令只能在任务快照对应的 AppContainer 中运行。沙箱限制可访问目录、入口程序、子进程、内存、时间、输出、网络和任务目录磁盘软预算。

AppContainer 是文件和网络权限边界，不是程序白名单。阶段 1 通过宿主入口白名单加“禁止子进程”保证只能启动受管理程序。

### 3.6 任务快照与回写

代码代理永远修改项目快照，不直接修改原项目。快照保留任务开始时的未提交修改，排除 `.git`、密钥、`.env`、缓存、构建产物和任务数据库，不跟随重解析点，并为基线文件建立哈希清单。

自动回写必须同时满足：原文件未变化；只修改普通文本源码、测试或文档；不删除或重命名；不修改保护文件；不包含二进制；不超过 20 个文件、1000 行和 1 MiB；可靠验证通过。

### 阶段 1：无模型 Windows 沙箱——已完成

只实现和验证沙箱基础设施，不接主模型、`WorkHost`、自动回写或网络代理。

- PowerShell 7 和 Python 3.12 来自应用自管目录，通过绝对路径配置；缺失或版本不符时失败，不自动下载。
- 禁止沙箱程序创建子进程。PowerShell、Python 和代码搜索工具由宿主分别启动。
- 入口程序必须精确匹配受管理白名单。
- AppContainer 不授予互联网、私网或回环网络 capability。
- 命令默认最多 5 分钟、4 GiB 作业内存、1 MiB 总输出。
- 任务目录 2 GiB 是每 0.5 秒监测的软上限；超限立即终止，但不宣称能阻止瞬间超写。
- 不支持时必须明确失败，不得降级为普通进程。

## 5. 审批恢复链

```text
模型请求工具
→ ActionGateway 判断需要确认
→ CodeAgentLoop 保存完整恢复点
→ CodeAgentProvider 返回 waiting_approval
→ WorkHost 原子保存检查点和审批记录
→ 用户确认或拒绝
→ WorkHost 创建恢复 Attempt 并调用 provider.resume()
→ CodeAgentLoop 从原工具调用处恢复
→ ActionGateway.resume() 产生执行结果或拒绝结果
→ 结果返回模型继续任务
```

恢复点必须包含模型消息、步骤和令牌计数、快照编号以及不可修改的原始动作请求。前端只能提交审批决定，不能替换工具名或参数。

## 6. 发布门槛

### 安全门槛

- 沙箱逃逸、未授权联网、未授权宿主文件修改、未授权保护文件回写、自动回写损坏原项目：全部为 0。

### 代码代理质量门槛

- 至少 30 个代码任务，每项运行 3 次。
- 简单修复成功率至少 90%，全部任务总体成功率至少 80%。
- 工具结果返回模型覆盖率 100%。
- 错误宣称测试通过为 0。
- 用户拒绝某动作后能够尝试替代方案。

### 功能开关

```text
code_agent_enabled
code_agent_auto_apply_low_risk
routing_mode = model | legacy
legacy_shadow_enabled
```

依次启用：沙箱测试 → 手动代码任务 → 自动回写 → 模型自动派单。出现安全违规时立即关闭 `code_agent_enabled`；路由异常时切回 `legacy`。

## 7. 明确不做

第一版不支持沙箱内直接联网、GUI 自动化、Git 提交或发布、系统设置修改、自动下载安装运行时、未经审批修改保护文件，也不把聊天 `AgentLoop` 复用为代码代理循环。
