# 情景 Agent 状态机设计

## 目标

情景模块不是固定剧情播放器，也不从任何示例复制地点、人物或台词。它先以“情景分析师”身份和用户讨论，把用户输入持续润色成当前情景提示词卡；用户确认后才切换为角色对话，后续回复始终使用当前卡片、当前角色风格和本情景历史。

## 状态与数据流

1. `drafting`：用户描述或修改想法，真实模型作为情景分析师回复。模型输出一段给用户看的讨论文字、一张可继续修订的情景卡、简短结构化摘要，以及卡片是否已具备开场条件。
2. `ready`：卡片已具备开场条件，但仍处于分析师阶段。用户可以继续补充，模型会重写卡片；只有用户点击“开始情景”才会切换。
3. `dialogue`：系统提示词替换为角色对话提示词。基础爱尔奎特说话气质、当前情景卡和本情景历史共同生效，不读取主聊天记忆，也不注入示例场景。

现有 `collecting` 数据迁移为 `drafting`。讨论消息保留并显示在讨论阶段；进入正式对话后只显示正式对话消息，但提示词卡仍可查看和修改，下一轮生效。

## 模型边界

分析师提示词只描述任务和输出结构，不包含便利店、陌生女性等示例。缺少真正影响开场的信息时自然追问一次；能从用户原文合理推断的内容直接补全，不用固定字段表审问用户。正式对话只接受当前卡片作为场景事实，旧卡片或其他情景不得进入请求。

## 界面

讨论阶段显示分析师名称、分析回复、当前卡片摘要和“开始情景”按钮。按钮只在卡片就绪且没有请求运行时可用。消息区、主输入框和提示词卡文本框使用与浅色/深色主题一致的细滚动条；输入框不显示浏览器原生拖拽角。

## 验证

先用失败测试固定状态转换、模型请求内容和无示例注入，再实现最小代码。最后启动真实 `web_api.py`，使用多个非便利店场景验证讨论、改卡、确认、正式对话和页面主题；模拟模型只用于可重复的单元测试，不能作为功能验收结论。
