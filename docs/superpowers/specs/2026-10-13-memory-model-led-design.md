# B 模型主导语义判断与可见纠正记录

依据：用户要求“直接让模型做大头”，并要求记忆代理自己能看到模型判断、以后能纠正。此要求替代上一版让字词相似规则证明语义的做法；原完整 B 验收范围不缩小。

## 分工

推荐采用现有后台记忆代理：读取处理包、当前目标和必要历史，批量作语义核对，输出保存/替代内容、逐条结论、原文引用、事项和判断理由。人物关系、指代、是否同一事项、语义改写、用户采纳等由模型判断，不再用字集合、相似度或删关系词作通过证据。

只调提示词不足以覆盖写入旁路；另建一个可以任意读写库的代理成本更高且会重复已有权限、同步和恢复机制。现有代理批量判断并通过现有事务写入，兼容成本较低；若后续证明现有处理包缺必要上下文，再补包的来源，而不重新开放全库。

程序只放行完全原句或数字等值写法；其他有含义变化的内容必须有已验证模型判断。程序检查引用确实存在、来源角色真实、明确数字冲突、无成功依据的审批/执行、权限与目标版本。模型结论不能解除这些硬约束；程序不再次用词语相似否决模型语义判断。

## 判断可见与恢复

模型判断、理由、具体引用和原始输出持久保存于任务回执及记忆附加信息。后续记忆代理读取被召回记录时得到该判断及出处，可根据新的用户原话改正旧结论；新会话可查看当前版本与更新关系。没有依据或不确定的判断分别保留处理记录，不能装成确定事实。

服务内签发的核对凭据绑定正文、来源、处理包、事项、目标版本和规则版本，防止模型自填“通过”绕过后台判断；重启时复用已持久判断，不重复调已完成模型。维护交接携带同一凭据，保持一次批量复核上限及30秒超时。签发密钥仅在本端隔离/正式数据库内部，永不发送模型或同步出去。

## 验证与范围

先复现上一轮两项误写，再用模型拒绝验证不入库、用模型修正验证入库与新会话检索；模型看不到的判断、伪造引用、伪造通过凭据、目标变化、硬数字冲突和重启恢复都要设测试。

保留现有类别、存储、同步、本机与云端入口。继续原计划的期限、Q17三条重放、完整离线与HTTP、18类各三次真实批次及独立审查；只有全部通过才打开C门槛。用户授权当前会话执行，无需再次确认；不部署、不推送、不处理生产数据。
