# C：统一上下文编排实施计划

> 执行说明：按任务逐项使用 executing-plans 流程；每项先构造能暴露问题的测试，再实现、复验并更新记录。本文件是待实施计划，不表示相关功能已经完成，也不授权部署、推送或修改生产记忆。

**目标：** 同一请求走普通回答、搜索、核查或预算收尾时，都保留同一份必要背景；长对话优先保留真正影响任务的内容，而不是各分支自行截取。

**总体做法：** 把现有记忆检索、角色提示和工具证据接到一个统一编排层。先整理带出处的候选内容，再统一决定保留与压缩，最后按调用用途生成输入；工具返回后产生新版本，后续回答和核查共用该版本。

**现有技术：** Python、现有模型调用接口、现有 SQLite 存储，以及项目现有自动测试工具。第一版不增加外部服务、向量库或每轮必需的额外模型调用。

## 范围与推荐

本计划中的“C”指用户提供的问题清单 C1—C4，不指某个尚未定义的部署方案。排除场景对话区。

| 做法 | 实施成本与维护影响 | 判断 |
| --- | --- | --- |
| 只调整提示词和截断长度 | 初期成本低；输入仍由多个分支重建，新入口容易再次漏背景 | 不采用 |
| 在现有链路上增加统一编排，逐项替换 | 中等成本；可以逐步验证和回退，保留已做的 A、B 改造 | 推荐 |
| 一次重写聊天、记忆、后台与云端 | 成本高；同时改变执行、持久化和同步，故障难定位 | 不采用 |

推荐成立的条件：现有搜索证据和记忆候选仍能通过适配层复用。若实施时发现某条输入在产生时就已丢失必要信息，先修其产生入口，不用扩大提示词或声称编排层能恢复已经丢失的信息。

本次承担：主回合统一输入、任务优先级、历史整理、调用前空间检查、核查与收尾一致性，以及其他执行入口的上下文输入契约。

后续 D、E 承担：复合播放/导航路由、后台完整结果展示、任务回执接回主综合、审批恢复刷新和图片恢复、命令行持久历史、云本地故障接替。C 提供这些工作可复用的输入格式，但不把它们记作本次已经修好。

## 必须共用的规则

1. 每个回合有唯一编号；每次工具完成或输入刷新产生递增版本。回答、核查和收尾标明使用的版本。
2. 保存原始输入与编排结果两份内容。压缩只改变模型本次看到的输入，不删除公开历史、不改真实记忆、不篡改工具结果。
3. 角色与运行权限、用户要求、记忆、网页材料分开标注。网页或记忆正文里的“忽略规则”不能变成系统指令；模型推断的任务目标也不能覆盖用户原话。
4. 相同候选、相同用途和相同预算必须得到相同选择。更换模型服务时，硬约束不变；容量较小时允许减少可选背景，但必须记录差异。
5. 一次性要求只在当前回合有效，不进入长期记忆或默认继承到无关后台任务。
6. 只调用当前入口实际允许的工具。继承背景不扩大权限、不越过审批、不让代码任务访问其工作目录之外的数据。
7. 影子对照只计算差异，不多调用模型、不多执行工具、不多记一次访问、不多写记忆。
8. 超限、摘要失败、附件不可用和未接入入口都要有明确状态；不能静默少看背景后报告完整核查。

## 统一输入应包含什么

这里的“契约”是各入口共同遵守的数据约定，不是把同一段完整聊天复制给每个执行器。

| 内容 | 必须携带的信息 | 使用规则 |
| --- | --- | --- |
| 回合身份 | 回合编号、版本、用户和会话范围、可信项目绑定 | 用于隔离和追踪，不从模型回答猜身份 |
| 当前任务 | 用户原话、当前目标、目标出处、仍未解决的问题 | 目标含推断时明确标注，保持原话可查 |
| 规则 | 角色、工具边界、输出要求、一次性要求及适用范围 | 按真实指令来源合并，不让数据冒充规则 |
| 历史 | 消息编号、角色、时间、主题、保留或摘要状态 | 摘要能回查来源；当前问题和必要上下文保持原文 |
| 记忆候选 | 记录编号、类型、状态、原因、项目、时间、可见范围、原始引用 | 假设、计划、已采纳和已执行不能混同 |
| 工具证据 | 调用编号、完成状态、结构化结论、来源、限制、原结果引用 | 失败不是成功；摘要不是已读原文 |
| 附件 | 受控引用、所属回合、类型、可用性、估算占用 | 本轮原图可用于主回答与核查；不把图片编码当文字计算 |
| 预算与选择记录 | 本次容量、输出预留、工具说明占用、已选内容、删减原因、缺口 | 用于解释本次取舍，不输出内部记录给用户 |

跨调用用途只允许四类变化：工具权限、输出空间、相关材料子集、是否需要图片。对同一候选最终答案作第一次与第二次核查时，相关附件和硬约束必须一致。

## 优先级与冲突处理

先按可见范围和项目授权筛选，再按与当前任务的关联选择；不能先拿全部用户记忆评分，再补做隔离。

| 顺序 | 内容 | 压缩与舍弃规则 |
| --- | --- | --- |
| 0：必须保留 | 运行规则、当前请求、本轮明确要求、已识别且仍有效的直接约束、当前未完成工具调用组 | 不静默删除；放不下就停止该调用并说明限制 |
| 1：任务核心 | 当前有效决策及原因、解决问题所需事实、关键成功或失败结果、决定取舍的限制与冲突 | 优先保留；可压缩叙述，保留状态、条件、出处 |
| 2：理解背景 | 指代所需历史、当前任务摘要、直接相关偏好与经验 | 按明确相关性选择；不能因较旧就一律舍弃 |
| 3：补充内容 | 关联主题、弱相关旧讨论、探索性材料 | 仅使用剩余空间；不能挤掉直接背景 |

候选进入任务核心的依据按顺序为：已确认的任务或项目绑定、明确事项引用、现有检索相关得分与关系信息。存储在热/温/冷区不决定其回答优先级；同一组内以相关性、证据状态、适用时间、稳定记录编号排序，时间不得越过相关性决定顺序。

当前用户明确更改旧选择时，以当前要求为本轮执行依据，仍保留旧记录出处和“本轮已更改”的标注；不在编排阶段自动改库。两条证据冲突且没有明确替代关系时，两边与冲突说明一起保留，不仅选择最近的一条。

同一段历史和热记忆优先按来源消息编号去重。没有编号时，仅对同角色、同时间和规范化后完全相同的正文合并；不得用相似度把“考虑采用”和“已经采用”合并。去重保留来源引用及规则标签。

## 空间不足时怎样处理

一次能看多少内容与整轮已经花费多少额度是两个限制，必须分开判断。复用现有用量账本，不在新编排层建立另一份累计账本。

本次输入上限取以下限制的较小值：经核实的模型容量减输出预留与安全余量、当前回合剩余额度减本次输出预留。工具说明、消息结构和附件占用也算入输入。模型容量从显式运行配置或适配器已确认能力读取；未知时不推断成无限容量，正式启用前必须补齐配置。

第一版安全余量为模型容量的 10%；主回答按现有模型输出上限预留，核查按其实际输出设置预留，收尾至少预留现有 128 个单位。估算沿用中文逐字、其他字符约四分之一的口径并单独计算消息结构；图片使用模型适配器确认的估算规则，无规则时阻止依赖图片的调用并报告未验证，而不是沿用万能的固定小值。

缩减按顺序执行：去除重复 → 舍弃弱关联补充 → 整理旧历史 → 缩短非关键工具叙述 → 再检查容量。每步都记录变更。

旧历史整理保留：目标、用户约束、决策及理由、完成与未完成状态、失败限制、开放问题、原消息编号。默认按用户回合分组提取和摘录，关键约束原文保留；不把一次助手建议升级成用户决定。必要时仍保留整组原文并舍弃低价值内容。

历史状态只能来自用户明确陈述、现有状态元数据或对应的可信工具结果；引用助手建议时保留“助手提出、用户未采纳”。无法可靠识别状态或否定范围的相关句子保留原文，不凭少数关键词生成新结论；若因此无法满足容量，报告背景缺口并有限收口，不以摘要名义补事实。

本次不新增摘要模型调用。以后需要更强语义摘要时，另行验证质量与成本；即使如此，摘要也只能作为带来源的背景，不能成为事实写入依据。

工具调用请求和对应回执必须完整配对，压缩以整组为单位。不能留下有调用没回执或有回执没调用的输入；当前等待审批的调用组不可压缩成已完成结果。

核心材料压缩后仍放不下：不发起注定超限的模型调用；已有可靠结果时返回有限结论和具体缺口，无可靠结果时说明本次不能完整处理。预算确已耗尽时不再为“补一句话”启动模型。
