# B 模型主导架构独立复审

日期：2026-10-13。结论：架构已允许可信模型判断放行关系改写，但仍有一个实测阻断及一个需补严格校验的授权缺口；不能宣布 B 整体通过。

只读检查 memory_semantic、memory_processing、memory_evidence，以及判断在 memory_turn、memory_extract、memory_agent 中的传递；未修改产品、测试或旧暂停报告。工作区在主任务中持续变化，以下是本轮所读版本的证据；本轮只执行一次有界探针，退出码0。

## P1：旧执行关键词仍在模型前直接否定忠实改写

- 用户原话：`上线已经办妥`。
- 候选内容：`上线已完成`。
- 实际结果：prepare 将它记为 unsupported，模型调用次数0、没有持久化判断、正式保存入口返回空记录。
- 根因：hard_gaps 通过旧 _clause_states 检查依据是否含执行“结果词”；“办妥”不在表内，于是把“规则没识别”当成“原话没有结果”。它既会在模型调用前硬拒，也会在模型给出有效判断后再次执行。
- 实际影响：代理没有机会承担语义判断；用户用自然语言表达真实完成状态时，忠实记忆仍会消失。继续扩词表只会把相同问题移到下一种说法。
- 建议：具体可证明的数值冲突继续硬拒；程序不能识别结论应转为模型核对。模型判断通过后，程序验证真实引用、完整上下文、签名与持久结果，不再靠旧词表推断语义是否成立。

## P1：更新授权字段允许缺失，需严格要求模型明确批准

静态证据：_validate_review 对 target 仅拒绝 change_authorized 恰为 false；该字段缺失、null、字符串等情况未被拒绝。same_subject、preserves_negation、preserves_conditions 同样只拒绝 false。

因此，全更新交给模型只是确保“有模型响应”，未确保响应明确确认这是同一事项且可更改该目标。建议目标更新必须要求 change_authorized is True；核心布尔字段必须类型正确且明确 true。模型缺字段应作为无效复核结果保留，不签发授权。此项仅静态确认，本轮未增加目标更新探针，不称已实际错误入库。

## 本轮正向证据

- 原话 `张三的老师是李四`、候选 `李四教张三`：模拟提供方返回 supported、完整引用及理由后，结果先交持久化回调，再签发本端凭据；正式保存入口实际保存关系改写。旧纯字词规则未否定这条有效模型判断。
- 同一探针为两条候选注入 signature=fake 的 review_receipt；正式保存均为0。它证明该伪造签名被拒，不代表穷尽所有攻击。
- 模型输入实际包含完整 packet 与 sources，来源保留完整原始分句；不是只给候选与字词规则结论。
- 更新强制模型核对修复已在复读时出现：存在 target 时，未经可信模型判断不能走原句快捷放行。此处仅静态确认，未执行更新并发探针。
- 旧记忆模型判断由 MemoryRef 随处理包传递；提炼输入显示判断、理由和引用，提示明确旧判断不是新证据；复核输入 target 含 metadata，也能看见已持久判断。

## 验证边界

本轮模型为固定模拟响应，证明处理、持久化、签名、正式入库路径，不证明真实模型判断质量。持久化回调用于观察调用顺序；真实后台数据库恢复与三次重试未在本轮复验。没有运行广泛旧测试、真实批次、并发提交、生产同步或部署；这些仍由主任务验收。新增阻断已立即通知主任务。

## 后续有限复审：模型判断仍被候选替代入口否决

主任务已移除审批/执行结果旧词表硬拒，并将授权布尔字段改为明确 true 校验；上文两个问题记录的是修复前快照，不作为当前未修复结论。

本次仅运行一个候选替代场景，真实隔离数据库、模拟模型响应，退出码0，未修改产品测试。

- 旧有效事实：`张三的老师是李四`。
- 当前用户原话：`张三现在拜王五为师`。
- 新候选：`王五教张三`，supersedes 指向上述旧事实。
- 模型输出：supported，same_subject/preserves_negation/preserves_conditions/change_authorized 全部 true，引用完整本轮原句，reason 为同一人更换老师，lifetime 为 long_term。
- 实际结果：prepare 成功生成带签名候选，prepared=1；正式 save_semantic_candidates 保存结果为空；旧事实仍 active，没有归档。
- 根因：候选替代入口在检查签名凭据前仍调用 _supersede_authorization，其事项匹配、明确替代词表及旧 evidence_gaps 没有消费可信模型判断。自然语言“拜王五为师”不能用“缺少改用词”否定已批准替代。
- 判定：P1，当前真正阻断；模型主导并未覆盖正式候选替代入口。已有受限的维持事实不能证明统一新建/纠正/替代/合并已经满足要求。
- 修复方向：可信签名明确授权该目标后，由程序重核目标权限、版本、来源引用与事务完整性；停止在该路径重跑语义词表。未获凭据的候选不能依此放宽。

附加缓存静态风险：_validate_review 的 durable 以 persist 存在或 cache/cached 非空认定；当传入旧缓存不匹配，重新请求模型后 cache 会成为新响应，即使未调用 persist，也会因 cached 原先非空被视为已持久。这属于持久证明变量混淆；正式队列当前均传 persist，因此本次不将它列为已复现正式后台阻断。建议显式记录“使用匹配且已持久缓存”或“本次persist成功”两种事实，避免调用方扩展时穿透持久门槛。

本次没有继续运行缓存攻击或随机探针，未验生产数据、真实模型、全部恢复与检索；新阻断已立即通知主任务。其余仍以当前测试证据分别判断，不宣布整体通过。

## 再次有限复审：旧原话阻止用户明确纠正

本次仅运行一个隔离正式后台准备入口场景，退出码0。旧缓存失效后被误认持久的问题已改为独立 durable_cache 变量；候选替代阻断由主任务新增测试修复，本段不重复以旧快照指控当前代码。

- 旧有效偏好：`我不喜欢蓝色`，版本1。
- 必要历史：用户消息 `old`，正文 `我不喜欢蓝色`。
- 当前用户原话：`我喜欢蓝色`，消息 `t`。
- correct 候选：`我喜欢蓝色`，仅引用 t，指向上述旧记录、期待版本1。
- 实际结果：MemoryReviewProcessor.prepare 的模型调用0，prepared updates=0；拒绝理由 polarity/完整原句的否定被直接反转；隔离数据库旧记录仍 active。
- 根因：未经判断时 hard_gaps 扫描全部 original_sources，包括历史旧用户原话，不区分时序及候选引用来源。因此旧否定无条件阻止新肯定，用户明确改变偏好不能交模型判断。
- 判定：P1，当前实测阻断。保护“不得丢原句否定”不能阻止用户后来明确纠正同一事项。
- 修复方向：候选与其当前引用的原话直接极性冲突可以硬拦；旧消息与新消息冲突应交模型结合时序、目标及用户变化授权判断，不得用旧消息抢先拒绝。新增此场景及“当前原话不喜欢、候选喜欢”的反向保护对照。

本轮其余核查为静态：缓存结果回调成功后才设置 durable_cache，旧匹配缓存复用可避免重复模型调用；跨重启签名键来自同一数据库；模型判断继续在记忆交接与提炼输入中可见。未运行跨重启/双端期限/新会话召回探针，不称这些完整验收已通过。新增阻断已即时告知主任务，产品和其他代理测试文件均未改动。
