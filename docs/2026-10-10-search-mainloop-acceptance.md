# A 部分独立验收报告

日期：2026-10-10。范围：主聊天的联网搜索回主回答链，对应原审计 A1—A8；排除场景对话区。

## 结论

**搜索接回主回答链的核心改造成立，但 A 的完整验收不通过。** 后续搜索证据未合并、核查背景及长答案截断、失败收口摘抄未核实摘要、辅助调用预算与用量记录仍有缺口。不能把“模型输入里出现记忆标记”或实时脚本显示 PASS 当成“正确结合记忆分析”。

本轮只新增独立验收探针并整理报告、下一阶段计划，没有维修运行代码，没有改真实长期记忆，没有部署或提交。B 可以先完成设计；记忆与搜索的整链验收必须等 A 收尾。

真实脚本的限制：

- 直接运行主循环，记忆手工放入系统消息，没有经过记忆会话、长期检索、提炼或云同步。因此只能检验“给定背景能进入回答”，不能证明“记忆库自然召回并融合”。
- 图片实际为乱码，缺图时脚本还会把跳过当 PASS；应使用可读且文字输入没有答案的图片，缺图算未验收。

- 网页读取多次约 21.4 秒超时，显著拖慢首字。脚本未接网页管家进度，不能因它显示进度时间为 0 就断言网页无进度。

## 六项必须收尾的缺陷

### 1. 后续搜索的证据和来源没有汇总

触发：入口已搜索一次，主模型随后自主搜索新价格。实测确有两次搜索，核查和交付来源却仅有第一次的网址，新事实不进入核查证据。

原因：回合已有入口证据包时直接返回它，不再合并后续工具回执。

影响：主回答可能使用新事实，核查却不知道它来自哪里；来源小气泡也会漏掉真正用到的网址。

收尾要求：所有搜索和原文读取按本轮统一汇总、去重并保持稳定来源编号；未整理的后续回执也必须标明证据等级，不直接升级为已核实事实。通过标准：入口搜＋模型补搜＋读原文，最后核查与交付来源完整对应实际使用材料。

### 2. 最终核查缺少必要任务背景

触发：关键记忆位于系统消息 1000 字以后，约束出现在较早用户历史，或由本轮非搜索工具返回。主回答能看到工具结果，核查不能；记忆尾部及历史标记也消失。

原因：核查自行截取首个系统消息前 1000 字，没有复用本轮必要任务背景。

影响：无法可靠识别违反用户决策、忽略工具结论或不遵守历史要求的回答。

收尾要求：从主回合形成同一份必要背景摘要，保留相关记忆的类型、状态与来源、本轮约束和可信工具结论；超预算时明确缺口，不静默裁掉后宣称完整核查。通过标准：较早明确约束与本轮工具限制均能阻止相反答案发布。

### 3. 核查失败仍转述未核实摘要

触发：没有整理事实，只有标为未核实的宣传摘要。兜底仍摘前两条材料，并以“现有材料只能确认”开头。

原因：安全收口在事实为空时回退到原始摘要拼接。

影响：证据整理失败后仍发布没有经过同等级检查的内容，措辞还把未核实转述说成可确认信息。

收尾要求：事实为空时只说明无法确认、具体缺口及必要后续动作；有事实时仅使用已验证条目。通过标准：失败路径不得出现摘要中独有、未获确认的宣传结论。

### 4. 辅助模型调用绕过预算

触发：总预算只有 1，材料整理模型仍被调用一次。

原因：材料整理和核查没有调用前预算守卫，主循环剩余预算也未统一扣除辅助用量。

影响：配置的整轮成本上限不是实际硬上限。

收尾要求：入口判断、整理、主回答、核查、重写共用调用前预留与调用后结算；预算不足时按已确认事实收口。通过标准：已耗尽预算不再启动辅助调用，失败与取消也准确结算；测试必须检查调用次数和剩余账。

### 5. 用量漏记、实际值被估算替代

触发：入口判定真实返回 123 输入、45 输出，账本变为估算 7 输入、0 输出；真实入口搜索提前返回时又完全漏记判定。

原因：判定返回的用量有外层包装，记账未解包；部分提前返回跳过记录。代码还存在主回答缺用量时拿空请求估算的路径。

影响：成本、预算判断和监控数据均可能偏低。

收尾要求：统一读取实际用量结构；所有出口在完成、失败、取消时结算；无实际用量时按真正发送的输入与产生的输出估算并标记。通过标准：123/45 原样入账；入口搜索路径也有判定记录；非空请求的估算不能为零。

### 6. 长答案尾部未经核查

触发：候选回答 2632 字，核查仅收到前 2400 字，尾部标记消失；发布并未相应裁成已核查部分。

原因：候选答案硬截取。核查整体载荷另有按字符串 9000 字符截断的代码风险，可能破坏结构；此附加风险未单独复现。

影响：回答尾部即使包含无依据结论，也不能被该次核查发现。

收尾要求：全文核查或先压缩形成最终候选再完整核查；结构化载荷按字段预算，保持可解析。通过标准：尾部无依据断言必须被拒绝或删除，最终发布文本每一部分都经过核查。

## 收尾顺序与最终门槛

1. 合并回合所有证据及来源，再修核查背景与全文覆盖。
2. 去掉摘原始摘要兜底，确保失败路径不会绕过质量门。
3. 修统一预算与用量解包、提前返回结算。
4. 修日期依赖测试；强化图片、未定义方案、入口漏搜、发布事件的实时断言。
5. 重跑相关测试及六项探针，并用临时记忆库通过真实记忆会话走“召回→搜索→主回答→核查→发布”。不得用手工系统记忆替代整链。

六项探针均无缺陷、相关测试全通过、真实场景的语义和来源检查成立，才可改写 A 的验收状态。网页历史气泡与主舞台来源位置未在本轮浏览器验收；生产云端版本和真实记忆库融合也未在本轮验收。读取超时另作体验改善，不用“搜索失败仍计数”代替延迟评估。
