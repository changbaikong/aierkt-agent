日期：2026-10-13。结论：仍有三个已复现的关键缺口，不能以新增测试通过宣布 B 完成。

只读审查产品与测试；未修改产品、测试、配置、生产数据或既有文档。检查范围包含 memory_binding、memory_evidence、memory_processing、memory_writes、memory_queue、memory_maintenance、memory_horizon、memory_retrieval、cloud_memory/store 与 worker；参考本轮执行记录和原 B/C 门槛报告。

## 1. P1：非执行类否定可以被删掉并直接保存

- 用户原话：`用户不喜欢蓝色`。
- 候选内容：`用户喜欢蓝色`，fact/reported，合法本轮来源编号。
- 实测：统一检查返回 supported；真实隔离数据库保存 `用户喜欢蓝色`。
- 原因：evidence_gaps 仅检查特定执行动词前的否定；_uncertain_items 判断候选所有字是否已出现，删除“不”不会产生新字。bind_evidence 的 negations 列表也没有单独的“不”。
- 后果：用户明确拒绝的偏好可以成为有效正向事实，完全绕过后台复核。
- 修复方向：逐事项核对命题极性，不能只为部署、执行等少数动词保留否定；增加“不喜欢→喜欢”“不允许→允许”的实际保存反例。

## 2. P1：同字重排后的相反关系被当成纯换词

- 用户原话：`张三管理李四`。
- 候选内容：`李四管理张三`，fact/reported，合法本轮来源编号。
- 实测：统一检查返回 supported；真实隔离数据库保存 `李四管理张三`。
- 原因：_uncertain_items 只比实义字集合，不检查主客体、关系方向；same_subject 的共同实义片段又能绑定该来源。
- 后果：关系方向颠倒的错误事实未经复核成为有效记忆。纯换词放行要求被扩大为“出现过这些字就可放行”。
- 修复方向：关系、主客体或词序变化无法证明等价时转 uncertain；保留“用→使用”的正向对照，新增方向反转的保存断言。

## 3. P1：混合候选仍可跨事项借用相同数值

- 用户原话：`项目预算3000元；广告预算9000元`。
- 候选内容：`项目预算3000元，广告预算3000元`。
- 实测：统一检查返回 supported；真实隔离数据库保存完整错误候选，广告预算被写成3000。
- 原因：bind_evidence 为各候选分句挑出原话后，将引用合并成一个证据池；evidence_gaps 对整条候选的数值只要求池中任意引用提供该值。split_subject_candidates 又因共同“预算”片段将两个事项继续合并，未恢复逐事项核对。
- 后果：单事项预算串值测试通过，仍无法保证混合候选中每个事项的数值有各自依据。这直接违反数字冲突硬拦截要求。
- 修复方向：保存逐 claim→原文的绑定关系，对每个分句的数值独立核对；事项拆分不能仅凭共享字段名合并。补上述混合候选及“项目3000、广告9000”正常对照。

### P1：inherited 可以把旧宾语当成新主语，保存错误关系并归档正确旧事实

- 旧有效事实：`张三的老师是李四`。
- 用户当前原话：`老师是王五`，合法本轮来源编号、目标旧版本1。
- 纠正候选：`李四的老师是王五`。
- 实测：统一回执 supported；正式 apply_semantic_update 保存错误候选为有效版本2，并将 `张三的老师是李四` 归档。
- 根因：inherited 分支只检查候选中省略原话之后的前缀是否“出现在旧正文”，不检查它是否原事项主语。`李四` 在旧事实中是老师身份，仍被拿来当作新候选所属人物。复核重写也重新进入同一门槛，不能靠再次调用此检查弥补。
- 后果：用户对张三老师的补充被转移成李四老师，旧事实还被正常版本事务替代；事务正确不能弥补依据判断错误。
- 修复方向：只有可证明与旧事项相同的明确主语才允许继承；无法确认“老师”指谁时进入后台复核，不能任意从旧正文抽取人物。新增正式纠正入口断言：候选不得把旧宾语升为新主语、旧行不得因此归档。

### P2：_literal_claim 删除关系连接词仍可能制造假等价

- 用户原话：`张三是李四的老师`；候选：`张三的李四是老师`。
- 实测：正式新建入口保存后者。该候选语句不自然，因此不将它与上项同等排序，但它明确证明“逐句保持语序”没有保存完整语法关系。
- 根因：全局删除“是”“的”让二者都变成 `张三李四老师`。它们不是措辞等价。
- 修复方向：别无条件删除承载关系的连接词；无法证明等价时 uncertain，保持普通“为/是”数值写法的正常对照。
