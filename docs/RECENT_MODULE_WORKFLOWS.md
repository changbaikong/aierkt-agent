# 近期模块工作与下次排查流程

更新：2026-09-29。这里是操作入口，不替代各模块的设计、测试和事故原始记录。状态以本次查看的工作区及验收产物为准；大量改动尚未提交，不能把“代码存在”“测试通过”“实际网页可用”混成一个结论。

## 共用工作流：先定故障在哪一层

1. **固定现场**：写下时间、账户/会话、访问或任务编号、当前页面、预期和实际结果。保留原请求、状态码、服务日志与最终页面；先不要反复发送可能已被接收的写请求。
2. **看入口**：确认正在运行的进程及配置、端口和健康接口；网页开发服务、正式后端和临时演示服务不能混认。健康只证明服务在线，不证明模型、数据库或回执链正常。
3. **沿链路逐层对齐**：浏览器请求及响应 → 后端接口和错误日志 → 模型/数据库/任务实际结果 → 事件或持久记录 → 页面渲染。第一次出现不一致的边界就是排查起点。
4. **先分类再动代码**：服务返回 402/余额不足或鉴权失败，是上游服务问题；连接超时或预算耗尽是时限问题；2xx 但字段缺失是契约问题；任务已成功而页面没显示是传递/展示问题。不要把所有情况都归为“模型没生成”。
5. **最小复现与验收**：先用一条有身份、可回查的请求复现，再补该边界的失败用例；最后从真实网页或任务入口走完一次。只测模型函数或看一张截图都不足以宣布修复。

事故记录统一写成：`症状与编号 → 首个不一致边界 → 原因及证据 → 改动 → 自动测试 → 真实入口复验 → 是否仍阻断`。失败案例保留，不用新一次成功覆盖旧证据。

## 开场白：进入页面的一句话

**近期完成的工作**：开场请求与主聊天展示分离，用一次标签页进入的访问编号防重；近期对话和确认过的事实可参与选题，联想台账负责冷却和判重。增加 100 条预备普通问候，服务端总预算 7.5 秒、网页等待上限 8 秒；无合适线索直接给预备问候，超时/失败也能交付。最近把联想后的普通问候间隔从两次改为一次，并将历史读取窗口扩大，避免工具命令先挤掉真实近况。个性化命中率及超时表现仍应在真实服务里继续观察。

**一次正常请求**：页面确认这次进入尚未交付 → 携账户、会话和访问编号请求开场接口 → 服务端限时读素材与台账 → 有合适线索才选题、措辞并记录 → 返回一句话 → 页面核对会话和访问编号后展示；前端请求失败或超过 8 秒，显示与该访问编号对应的预备问候。刷新、切页再回来不应重新问候。

| 看到的症状 | 先查什么 | 常见原因与下一步 |
| --- | --- | --- |
| 一直显示“生成中”或空白 | 浏览器请求是否发出、是否在 8 秒结束；页面是否仍属于同一会话 | 外部切页取消应静默；内部超时须交付预备问候。核对前端终止定时器、进入槽和当前会话，不要只加长动画。 |
| 总是普通问候/同一句话 | 直接请求开场接口看状态码，再看 `data/errors.log` 和开场模块的信息日志 | 曾有接口 500 被前端兜底掩盖；也可能是 402、模型失败、结构不合格、无候选、台账未写成或预算耗尽。先分清“接口失败”与“成功选择普通问候”。 |
| 模型服务报余额不足 | 保存原始 402 与发生时间，对照其他模型请求 | 先恢复额度或服务可用性，再用同一类请求复验；不要改选题规则，也不要把该回合算作模型质量失败。预备问候是可用性兜底，不是服务恢复的证据。 |
| 连接/读取超时 | 分别计时素材读取、选题、措辞、台账写入及总耗时 | 两段模型调用与同步数据库操作曾挤占旧预算；要在真实后端进程量时间，并保持后端截止早于前端。超时后仍须交付预备问候，不得无限积压读取任务。 |
| 有近况却从不提，或总重复旧事 | 检查候选在过滤前是否已被数量上限挤掉、14 天窗口、最近一次普通问候与线索冷却 | 过滤应先于限量；线索在 7/30 天内不重复，模型返回的引用必须属于本次候选，主题键也要复核。不能为了提升命中率关掉判重。 |
| 接口已有内容、页面没有 | 比对响应、访问编号、账户/会话、页面请求取消和展示状态 | 错会话的旧响应必须丢弃；同一进入交付过问候后不重演。前端和后端各自能兜底，仍要查清是哪一层降级。 |

**复验**：运行 `python -m pytest tests/test_opening_greeting.py tests/test_web_api.py -q`；在前端目录运行开场相关测试和 `npm run build`；真实后端分别模拟正常、有候选、402/断连、慢读取和超时，再核对网页 8 秒内有内容、访问编号不串台、台账不误记。测试不能证明当前模型账户有余额。

## 情景模块：先讨论设定，确认后再对话

**近期完成的工作**：独立会话、数据库、附件、提示词和运行循环；状态为 `drafting`（与分析师讨论）、`ready`（卡片待确认）、`dialogue`（正式对话）。角色对话和 Chatbot 模式在首次设定后锁定；角色对话只由当前情景卡控制口吻，Chatbot 的人设卡仅在 Chatbot 生效。分析可修改卡片，正式对话在用户明确点击开始后才进入；改卡从下一轮生效。页面按账户恢复情景、处理图片/文档与表情，但真实模型体验仍需持续复验。

**每次修改的顺序**：先定模式和阶段的输入/输出契约 → 查独立存储和接口的账户作用域 → 检查实际发给模型的消息优先级与卡片版本 → 检查页面每个入口（含预览） → 跑阶段、隔离、重试和刷新测试 → 用至少两套无关设定走真实模型全程。

| 看到的症状 | 优先定位与规避的弯路 |
| --- | --- |
| 看似聊起来却是固定剧情 | 先核对端口上的进程是否为真实后端；临时演示服务曾占用端口。固定测试提供器只能证明流程，不证明真实分析质量。 |
| 讨论阶段变成角色台词或自动开聊 | 查服务端阶段及页面状态；只有用户确认卡片才能从 `ready` 进入 `dialogue`。结构化回复虽是合法 JSON，缺必填字段也须受控重试，不得把散文当分析结果。 |
| 角色、口吻或旧设定串台 | 检查当前情景卡优先于历史摘要；“你/我”在分析阶段的角色映射；角色模式不能注入 Chatbot 人设。不要用更长的固定风格或三句气泡模板去压住问题。 |
| 切账户、刷新、附件预览出错 | 创建、读取、上传、预览和当前情景编号都要带同一账户；页面位置与情景内容分别恢复。失败的创建请求不能留在去重缓存里。 |
| 发送超时后重复消息或改卡不生效 | 同一轮重试复用回合编号；生成期间拒绝半途改卡，完成后保存并让下一轮读新卡。对“已接收但回执丢失”做反例测试。 |
| 只有图片目录为空时失败或表情越来越慢 | 空目录仍应能文字回复；限制目录扫描的文件数与读取总量，单张图片重新校验时不重扫全集。 |

**复验**：`python -m pytest tests/test_scenario_api.py tests/test_scenario_runtime.py -q`；前端运行 `npm test` 和 `npm run build`（以现有脚本为准）；真实网页覆盖两种模式、三阶段、改卡、重试、附件、刷新与窄屏。核对“发送给模型的内容、数据库保存的卡、页面所见”三处一致，不泄露内部思考或隐藏规则。

## 代码代理：隔离改代码、验证，再决定是否回写

**近期完成的工作**：阶段 0–3 的入口/权限、Windows 隔离、独立快照与任务 worker、可恢复审批、可信测试和有恢复能力的回写均已实现；自动回写开关仍默认关闭。阶段 4 的模型选路工程已落地。2026-09-29 01:47 的 62 例各跑 3 次题库记录为 186/186、代码代理召回 36/36；这只是离线选路证据。最近一份 30 条网页人工记录为 27/30，低于至少 29/30 的门槛，其中 5 个代码任务的实际证据为已验证且有补丁，但对话回执仍说未验证、无补丁。回执展开嵌套事件结果的修正已在工作区，尚需用新网页批次复验，不能宣称阶段 4 完成。

**安全工作流**：确认用户给出的项目根目录与任务范围 → 在排除密钥/产物的快照中运行受管代码工具 → 记录模型编辑和命令证据 → 由宿主指定可信测试复验最终快照 → 生成补丁与风险清单 → 若开启回写，先核对基线、路径身份、项目锁、审批原因和取消信号，逐文件事务失败则恢复 → 通过后台事件与对话回执把真实状态交付用户。审批只放行允许的风险类型，不能替代测试或覆盖冲突。

| 看到的症状 | 先查什么与处理原则 |
| --- | --- |
| 没有派给代码代理 | 先查服务进程实际加载的路由模式、代码代理和可信测试配置，再查首次工具选择与后续补救。402/超时不能算选路错误；题库满分不等于网页通过。 |
| 任务排队/停在审批 | 按任务和尝试编号查工作账本、worker、审批原动作与恢复点；不能用前端新参数替换已批准动作。已接收但无最终回复的请求先核账，不重发。 |
| 说“测试通过”却不能回写 | 看宿主可信测试是否针对最终快照成功，测试命令是否由受信配置指定。普通命令退出码 0 和模型自述都不构成验证。未验证、二进制、超限变更保留补丁。 |
| 补丁已生成、对话却说没有 | 对齐提供器结果、主机事件的嵌套输出、回执桥和页面展示；本次踩过只读顶层字段的坑。修复须用真实事件形状做端到端回归。 |
| 回写冲突、取消或恢复失败 | 停止新事务，保留恢复包；重查文件内容、父目录是否被替换及用户同时编辑。取消要深入逐文件事务，批准不能绕过路径/内容复核，不要手工覆盖用户版本。 |

**复验门槛**：专项测试和真实隔离运行证明快照不泄密、不联网、原项目不变；可信测试必须在最终内容上通过；完整 62×3 路由题库达到既定门槛后，再跑 30 条真实网页回合（其中 5 条实际代码任务）并人工逐条评审，至少 29 条正确、5 条代码任务合格，未授权持久操作与安全违规为零。复验操作按 `docs/superpowers/plans/2026-09-28-code-agent-matrix-web-acceptance.md`；未达到前保持旧默认路由和自动回写关闭。
